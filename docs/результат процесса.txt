AGENTS.md — инструкция для ИИ-агентов





+-1. Исправляем противоречия в документации.

Берём PDF с аудитом как список потенциальных проблем. Идём по пунктам:
- находим указанные места в документах;
- сверяем их между собой;
- обсуждаем, какое решение принимаем;
- вручную исправляем документы;
- отмечаем исправленное.
Важно: не принимаем все 37 замечаний на веру. Некоторые могут оказаться не конфликтами, а сознательными различиями или необязательными деталями.


+2. Создаём документ 00_MASTER.md.

Это центральная точка входа в документацию. В нём будут:
- краткое описание игры;
- основные принципы проекта;
- структура документации;
- назначение каждого документа;
- указание, какой документ отвечает за конкретную механику;
- правила разрешения противоречий между документами.
Он не должен дублировать остальные документы. Его задача — помогать быстро ориентироваться.


+3. Настраиваем AGENTS.md.

Объединяем две вещи:
- постоянные правила для ИИ-агентов, которые должны соблюдаться при любой работе над проектом;
- твой AI_TZ_Guide_for_Codex.md — инструкцию по подготовке подробных технических заданий.
При этом сам гайд оставляем отдельным файлом. Не нужно превращать AGENTS.md в огромную инструкцию на сотни строк.


4. Определяем MVP.

Выбираем минимальную, но реально работающую версию игры. Определяем:
- какие механики обязательны;
- какие системы нужны для их работы;
- что можно отложить;
- что конкретно должно работать в первой версии.




5. Начинаем разработку.

Работаем небольшими задачами:
1. ИИ изучает существующий код и получает конкретное ТЗ.
2. Предлагает изменения.
3. Реализует только согласованную задачу.
4. Запускает проверки и тесты.
5. Ты проверяешь результат.
6. Если всё работает — принимаешь изменения и отправляешь их в GitHub.
Архитектурные изменения без твоего разрешения не проводятся.
